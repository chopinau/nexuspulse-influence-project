### 1. Vercel Deployment vs. Localhost (The "Python" Problem)
**Issue:**
*   **Localhost:** Your local machine has Python installed. The Next.js API route (`app/api/agent-forum/route.ts`) uses `child_process.spawn('python', ...)` to run the analysis script. This works perfectly locally.
*   **Vercel:** The standard Vercel environment for Next.js is **Node.js only**. It does **NOT** have Python installed in the runtime environment where `spawn` is called. Therefore, `spawn('python')` fails silently or times out, leading to "Report Generation Failed".

**Solution:**
To run Python on Vercel, we must use **Vercel Serverless Functions for Python**. We cannot just spawn a process from Node.js.
*   **Plan:** We need to migrate `python_backend/report_engine_only.py` to a proper Vercel API route structure (e.g., `api/index.py` or similar) so Vercel treats it as a serverless function, OR we keep the current structure and I guide you to deploy the Python part separately (e.g., on Railway/Render) and have Next.js call it via HTTP.
